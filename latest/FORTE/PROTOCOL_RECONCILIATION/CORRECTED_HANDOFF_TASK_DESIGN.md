# Corrected handoff — task design

The recovered task roles and screening criteria remain useful. Only selector and claim language change.

## Keep unchanged

- Core tasks 0/1/5/6 for friction evidence.
- Need for a non-degenerate delayed-failure task for E3/E6.
- Need for a continuous/off-grid task with measurable force resolution for E7.
- Need for a mass-sensitive rigid/dynamic task and a joint-meaningful task for E8.
- π0-independent task qualification and matched root/physics/state design.

## Replace

- Replace every primary `min F subject to p>=rho_sel` rule with expected-Utility argmax.
- Remove `rho_sel` as a locked runtime field.
- Retain an empirical `rho_env` only for evaluation-frontier labels; rename clearly as evaluation-only.
- Reframe Minimum-Reliable as an optional diagnostic ablation, not the final claim or required final arm.
- In claim maps, replace “Minimum-Reliable selector” with “Full Expected Utility versus Success-Only” and “Point versus Posterior Utility.”

## Required causal control

Every promoted task should support Query-Ignored versus Active Query with the same initial state, P4-B action, duration, and post-query physical state. A task that cannot provide this matched control cannot carry a causal information-benefit claim.

## Required paper language

Use task-aware force adaptation, low-cost force selection, success–force tradeoff, Utility-optimal selection, and posterior-aware selection. Do not promise the absolute minimum feasible force.
