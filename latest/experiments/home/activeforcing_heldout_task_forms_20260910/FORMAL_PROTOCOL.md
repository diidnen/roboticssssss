# Conditional formal held-out task-form protocol

Status: NOT_EXECUTED; conditional specification only. The final task/root/evaluator manifest may be frozen only after VLA qualification and compatibility checks. No feasibility retraining is permitted.

Select qualified tasks by distinct supported forms first, then prefer category C (same manipulated object as training), and report category D separately. Deterministic tie break: repository task ID. Do not choose using AF results. Preferred 4–6 tasks across at least three forms is a target, not an admission requirement. If no task qualifies, select none and report NOT_TESTED.

For each admitted task use three predetermined in-support object-friction conditions (0.30,0.50,0.90), two prospectively reserved and audited fresh roots, and Fixed-3/4/5/AF. Task-specific native mass stays fixed; new-object native mass is disclosed as part of the category-D confound. Do not assign formal root IDs or run their physics before the candidate interface and task set pass. All methods must restore one established grasp, perform the same diagnostic query, share the identical post-query state and first online VLA chunk, and use the same frozen VLA, cadence and terminal evaluator. Only the grip-force strategy differs.

Preserve current utility `p*(5-F)/5 + (1-p)*(-1)`, force grid 3:0.05:5, the three frozen feasibility checkpoints, the original positive-mixture friction posterior/quadrature and low-force tie break. The current categorical task code rejects unseen IDs. Any minimum compatibility encoding must be explicitly justified and frozen, not silently aliased or learned from new labels. No such migration is currently selected.

For every context compute a decision-only GT reference with the same model/context/grid/utility and delta belief at true object-side friction. Label the GT diagnostic as privileged; do not claim its friction input is observable and do not use it to choose tasks. No physical GT branch is required.

Task success is terminal success of the complete downstream frozen-VLA task under the maintained grasp. Record native predicate and task-specific physical predicate separately where the former is inadequate. Freeze all geometry, containment/orientation/contact/release checks and horizons before AF outcomes. The original basket evaluator cannot be applied to insertion/extraction by renaming a target.

For fixed outcomes (3,4,5): 111 → requirement class 3; 011 → class 4; 001 → class 5; 000 → unresolved; all other patterns → non-monotonic. Do not drop those last two groups or impute a threshold. Compute global Spearman only on resolved contexts with nonconstant variables; per-form correlation only when sample size and variation permit, with n and uncertainty. A monotonic pattern alone does not identify a force-related cause; inspect failure evidence.

Report each form separately: tasks, contexts, four success counts/rates, selected setpoint, measured non-release squeeze, bilateral-contact-conditional squeeze, paired AF-only/baseline-only/both/neither successes versus Fixed-5 and Fixed-4, dominant failure mechanism and AF–GT force MAE. Paired contexts are the analysis unit; roots are the replication unit. Small-n form estimates are descriptive, with no universal reliability claim.

No retries for slips, drops, bad force decisions, geometric failure or negative scientific results. Preserve invalid infrastructure attempts separately; only repairs documented without task outcome selection may lead to another attempt. Hash selected tasks, evaluators, source, checkpoints and root plan before first formal branch; retain all admitted branches; analyze once and stop.
