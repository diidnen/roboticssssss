# Frozen VLA-only development qualification protocol

Frozen before any new-task VLA outcome or AF inference. No AF model is called for task selection.

Admission threshold: at least **5/6 successful development contexts**, comprising roots 5100 and 6100 × friction 0.30, 0.50, 0.90. These are development identifiers, not formal roots. A task must also pass all six maintained-grasp scope criteria. No lower threshold or outcome-driven retry is allowed. A run that never establishes a grasp is a VLA qualification failure, not an AF force-selection failure. Infrastructure errors are retained separately and cannot become task failures or successes.

The conservative setpoint is Fixed-5, using the frozen force servo and VLA-controlled opening semantics. The original frozen checkpoint, observation adapter, online inference every ten steps, and native arm commands must be retained. Qualification from a native reset may establish the grasp using the VLA before assessing the downstream portion; such a result alone does not verify the common P4B post-query interface required for the formal experiment. That additional gate remains mandatory.

Before physics, preflight task-config loading, task-ID resolution, actual assets, terminal evaluator, force controller and complete VLA observations. Prioritize native book-to-caddy (`libero_10:5`), wine-to-rack (`libero_goal:9`), bowl extraction (`libero_spatial:4`), and drawer opening (`libero_goal:0`) for compatibility inspection, in that fixed order. These are category D candidates, not a selected formal set. Native factory insertion and gear meshing remain a separate controller-compatibility track.

Terminal evaluators must be frozen before outcome collection. Native LIBERO position-only success is recorded as a native semantic metric; it does not establish successful insertion or reorientation. No task may qualify as a genuinely different form using a predicate that cannot distinguish the required behavior. If a faithful frozen evaluator or established-grasp interface cannot be supplied from repository evidence, record NOT_TESTED rather than invent an outcome or handoff.

No feasibility training, no task-code migration, no new-task AF force decisions, and no formal roots are authorized by this qualification manifest until the preceding audit and compatibility gates pass. This is a scientific gate from the user's requested sequence, not a request for additional permission.
